# Decision log

Each entry records a decision, why it was made, and what it affects. Superseded decisions stay in the log.

## D-001 - Target .NET 10 LTS instead of .NET 8 (2026-09-29, owner-approved)

The specification asked for ASP.NET Core 8. .NET 8 support ends on **10 November 2026**, six weeks after this
project started. After that it receives no security patches. .NET 10 is the current LTS release, supported until
November 2028, and was already installed. The architecture is unchanged; only the target framework differs.

## D-002 - PostgreSQL 16 (2026-09-29, owner-selected)

Chosen over MySQL 8 for exact `numeric`, transactional DDL, row-level locking with `FOR UPDATE SKIP LOCKED`,
exclusion constraints for effective-dated masters (no overlapping validity periods), `jsonb`, and data checksums.

## D-003 - Owner Dashboard is a normal browser application, not a PWA (2026-09-29, owner-selected)

There is no manifest and no service worker. The dashboard still labels all data as live, delayed, cached or
unavailable.

## D-004 - Development database on port 5442

A separate PostgreSQL 17 Windows service (another system) already listens on 5432 on the development machine.
SupermarketBilling uses its own Docker container on 127.0.0.1:5442 and never touches the other service.

## D-005 - Browser talks only to its own origin

Each Next.js app forwards `/api/*` and `/health/*` to the API through runtime route handlers
(`@sb/web-shared/api-proxy`). The browser never calls the API origin directly. This keeps future session cookies
first-party, `HttpOnly` and `SameSite=Strict`, avoids CORS, and means only the web server needs to know the API
address.

Next.js `rewrites()` were tried first and rejected. They fix the API address at build time, so an installed
release could not be pointed at a different store server; the release smoke test caught this. The route handlers
read `API_INTERNAL_URL` on every request. The API honours `X-Forwarded-For` only from loopback proxies, so
per-client rate limiting still sees each counter's own address.

## D-006 - Least-privilege database roles

The runtime account cannot run DDL, TRUNCATE, or alter triggers. Migrations run as a separate schema-owner account.
Immutability of ledgers is enforced by database triggers as well as by application code.

## D-007 - UUIDv7 identifiers

Primary keys are time-ordered UUIDv7 values generated by the application. They are safe to create offline on
devices (collections), are index-friendly, and don't leak row counts. Human-facing document numbers
(invoice, receipt, challan) are separate, sequential and unique per series.
